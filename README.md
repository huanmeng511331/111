# HSE 隐患上报与闭环管理 Demo

面向现场培训与 Demo 演示的 HSE（安全、健康、环境）隐患闭环演示系统：现场人员上报隐患，安全管理人员审核并分派责任人，责任人提交整改措施与完成情况，审核人员验收后关闭隐患，看板实时反映状态变化。

> 本项目为**演示项目**：不连接任何真实生产系统，全部数据为模拟数据，不包含真实人员信息或敏感文档。

## 1. 技术栈

| 分层 | 选型 | 用途 |
|---|---|---|
| 前端框架 | Vue 3 | 页面组件、状态与交互逻辑 |
| 前端工程化 | Vite 6 | 本机开发服务器、热更新与生产构建 |
| 前端组件库 | Element Plus 2 | 表格、表单、按钮、弹窗、菜单、标签等后台组件 |
| 后端框架 | FastAPI | REST API、请求校验、自动接口文档 |
| 数据库 | SQLite（Python 标准库 sqlite3） | 本机单文件数据库，保存业务数据与演示初始数据 |
| 接口风格 | JSON REST API | 前后端联调与业务操作 |

## 3. 环境要求

- Python 3.10+（已在 Python 3.12 验证）
- Node.js 18+（已在 Node 20.18 验证）与 npm
- 无需单独安装数据库服务，SQLite 数据文件位于 `backend/demo.db`

## 4. 安装与启动

### 4.1 后端（端口 8000）

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

- 接口文档：<http://localhost:8000/docs>
- 健康检查：<http://localhost:8000/api/health>
- 首次启动自动建表，并在隐患表为空时写入 10 条模拟演示数据（重复启动不会重复写入）
- 可选：设置环境变量 `HSE_DB_PATH` 指定其他数据库文件路径；如删除 `backend/demo.db`，下次启动会重新生成演示数据

### 4.2 前端（端口 5173）

```bash
cd frontend
npm install
npm run dev
```

- 页面访问地址：<http://localhost:5173>
- 开发模式下 Vite 将 `/api` 代理到 `http://127.0.0.1:8000`，需先启动后端
- 如后端不在 8000 端口，可用 `VITE_API_TARGET=http://127.0.0.1:8001 npm run dev` 覆盖代理目标
- 生产构建：`npm run build`（产物在 `frontend/dist`）；`npm run preview` 可在 <http://localhost:4173> 预览构建产物，预览服务同样代理 `/api` 到后端
- 如端口被占用，Vite 会自动选择下一个可用端口，请以终端输出地址为准

## 5. 页面与接口

### 5.1 页面（4 个业务视图 + 404）

| 路由 | 页面 | 说明 |
|---|---|---|
| `/dashboard` | 统计看板 | 隐患总数、待审核、整改中、待验收、已关闭、超期统计；状态/等级/类型分布与近 7 日上报趋势 |
| `/hazards` | 隐患台账 | 编号、类型、等级、位置、责任人、整改期限、状态；支持状态/等级/类型筛选、关键字搜索、超期过滤、排序与分页 |
| `/hazards/new` | 隐患上报 | 位置、类型、描述、等级、上报人、整改期限与模拟图片 URL；含必填/长度/日期校验 |
| `/hazards/:id` | 隐患详情 | 上报信息、整改要求、整改结果、状态流转记录；按状态提供审核分派、提交整改、验收关闭/退回 |

### 5.2 后端 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/hazards` | 隐患列表，支持 `status`/`level`/`type`/`keyword`/`overdue_only`/`page`/`page_size`/`sort_by`/`sort_order` |
| POST | `/api/hazards` | 上报隐患（自动生成 `HZ-YYYYMMDD-NNN` 编号） |
| GET | `/api/hazards/{id}` | 隐患详情（含状态流转记录） |
| PATCH | `/api/hazards/{id}/assign` | 审核并分派责任人，待审核 → 整改中 |
| PATCH | `/api/hazards/{id}/rectification` | 提交整改措施与结果，整改中 → 待验收 |
| PATCH | `/api/hazards/{id}/acceptance` | 验收：`pass` 关闭（待验收 → 已关闭）或 `reject` 退回（待验收 → 整改中） |
| GET | `/api/hazards/statistics` | 统计卡片、状态/等级/类型分布与近 7 日趋势 |
| GET | `/api/hazards/dictionaries` | 筛选项字典（类型、等级、状态、责任人候选） |

### 5.3 状态规则

| 当前状态 | 可执行操作 | 下一状态 |
|---|---|---|
| 待审核 | 审核并分派 | 整改中 |
| 整改中 | 提交整改 | 待验收 |
| 待验收 | 验收通过 | 已关闭 |
| 待验收 | 验收退回 | 整改中 |

非法状态流转返回 `409`（`INVALID_STATUS_TRANSITION`），参数校验失败返回 `422`，不存在的隐患返回 `404`。

## 6. 演示路径（验收脚本）

1. 打开 <http://localhost:5173>，在「统计看板」记录当前待审核/整改中/已关闭数量。
2. 进入「隐患上报」，填写示例数据：类型「消防」、等级「一般」、位置「二号厂房东侧消防通道」、描述「消防通道堆放杂物，影响紧急疏散」、上报人「演示用户」、整改期限选未来日期，提交后自动跳转详情页，状态为「待审核」。
3. 在详情页点击「审核并分派」，选择责任人（如「赵磊（后勤部）」）并设置整改期限，状态变为「整改中」。
4. 点击「提交整改」，填写整改措施「已清理并设置禁放标识」与完成情况，状态变为「待验收」。
   - 可选：在验收弹窗选择「退回继续整改」，验证退回后状态回到「整改中」。
5. 点击「验收处理」选择「验收通过并关闭」，填写验收意见，状态变为「已关闭」，流转记录写入完整链路。
6. 回到「统计看板」刷新，可见待审核/整改中数量减少、已关闭数量与闭环率上升。
7. 在「隐患台账」按状态「已关闭」筛选并搜索刚上报的编号，验证查询与筛选能力。

风险提示：

- 本演示未实现登录与权限控制，页面中的「安全管理员」身份仅作展示，操作人字段由表单填写。
- 演示数据中的图片链接为不可访问的示例地址，仅用于展示附件字段能力。
- 时间字段使用服务端本地时间（容器默认 UTC），跨时区演示时请留意时间展示差异。
- 前端通过自定义 resolver 对 Element Plus 做深度按需引入（`element-plus/es/components/<component>`），
  避免整库打包。若在内存小于 2GB 的机器上执行 `npm run build` 出现 `Killed`，请先关闭其他占用内存的进程后重试。
